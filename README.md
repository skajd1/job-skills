# 자소서 프로젝트

기업별, 직무별 자기소개서를 Markdown으로 관리하는 프로젝트입니다.

## 폴더 구조

```text
result/
  기업명/
    직무명YYMM.md
```

- 실제 기업 자기소개서는 `result/` 아래에 작성합니다.
- `result/` 아래 1단계 폴더는 기업명으로 작성합니다.
- 파일명은 `직무명YYMM.md` 형식을 권장합니다.
- 같은 기업에 여러 직무 또는 지원 시기가 있으면 파일을 분리합니다.
- 파일명에는 공백보다 하이픈(`-`) 또는 괄호를 사용합니다.
- `result/`는 실제 지원서 본문을 담으므로 Git 추적에서 제외합니다.

## 작성 규격

자세한 작성 규칙은 [자소서_작성_규격.md](자소서_작성_규격.md)를 따릅니다.

항상 같은 작업 흐름을 유지하기 위해 [자소서_작업_워크플로우.md](자소서_작업_워크플로우.md)를 우선 적용합니다. 문항이 2개 이상이면 문항별 초안 작성은 subagent에 분담하고, 최종 통합과 검수는 메인 Codex가 수행합니다.

기업별 문항을 작성할 때는 [자소서_작성_요령.md](자소서_작성_요령.md)의 기준을 함께 적용합니다. JD 분석, 기업 맞춤성, STAR 경험 구조, 수치 기반 성과, Humanizer 검수 후 덮어쓰기를 기본 흐름으로 둡니다.

새 파일을 만들 때는 [자소서_템플릿.md](자소서_템플릿.md)를 복사해 기업명, 직무명, 지원시기, 문항, 답변을 채웁니다.

## Humanizer

AI 초안 문체를 줄이기 위해 `im-not-ai`의 Codex용 `humanize-korean` 스킬을 설치해 사용합니다.

- 설치 위치: `C:\Users\wooch\.codex\skills\humanize-korean`
- 사용법: 새 Codex 세션에서 `$humanize-korean`을 호출하거나, "이 자소서 AI 티 없애줘"처럼 요청합니다.
- 기본 흐름: 초안 작성 후 `humanize-korean` 검수를 거친 문장을 같은 `.md` 파일에 덮어씁니다.
- 최종 산출물은 `result/기업명/` 폴더 안의 Markdown 파일 1개만 남깁니다. 별도 초안 파일이나 humanizer 결과 파일을 따로 두지 않습니다.
- 프로젝트 사용 기준은 [humanizer_사용법.md](humanizer_사용법.md)를 따릅니다.
